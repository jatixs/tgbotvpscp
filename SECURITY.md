# Политика безопасности

## Поддерживаемые версии

Мы настоятельно рекомендуем всем пользователям использовать последнюю версию бота для обеспечения стабильности и безопасности. Патчи безопасности выпускаются только для текущей мажорной версии.

| Версия   | Поддержка          | Примечание                  |
| -------- | ------------------ | --------------------------- |
| 1.25.x   | :white_check_mark: | Последняя стабильная ветка  |
| < 1.25.x | :x:                | Устарело (Не поддерживается)|

## Как сообщить об уязвимости

**ПОЖАЛУЙСТА, НЕ создавайте публичные Issue (задачи) на GitHub для уязвимостей безопасности.**

Если вы обнаружили уязвимость в этом проекте (например, в Telegram боте, WebUI или скрипте мониторинга нод), пожалуйста, отправьте электронное письмо мейнтейнерам или свяжитесь с ними через личные сообщения в Telegram.

### Что нужно включить в ваш отчет:
* Подробное описание уязвимости и её потенциального влияния.
* Файл(ы) и номер(а) строк, где обнаружена проблема.
* Пошаговую инструкцию для воспроизведения уязвимости (или скрипт Proof of Concept).
* Детали окружения (например, версия Python, ОС), где возникла проблема.

### Сроки реагирования
Мы подтвердим получение вашего отчета в течение **48 часов**. Мы стараемся устранять критические уязвимости и выпускать обновления (хотфиксы) в течение 7 дней после подтверждения.

## Лучшие практики безопасности при деплое

Чтобы ваша инфраструктура (бот и VPS) оставалась в безопасности, придерживайтесь следующих рекомендаций:
1. **Reverse Proxy (HTTPS):** Никогда не запускайте WebUI через обычный HTTP в продакшене. Обязательно используйте обратный прокси-сервер (Nginx, Caddy или Traefik) и настраивайте SSL/TLS сертификаты (например, Let's Encrypt).
2. **Изоляция сети:** Ограничьте прослушивание порта WebUI (по умолчанию `8080`) до локалхоста (`127.0.0.1`) и пробрасывайте его только через защищенный прокси. Не открывайте порт на `0.0.0.0` без надежного брандмауэра.
3. **Надежные учетные данные:** Устанавливайте сложный пароль от WebUI. Система использует надежный алгоритм хэширования Argon2, но слабый пароль все равно может быть подобран брутфорсом.
4. **Переменные окружения:** Надежно защищайте файлы `.env` и `config.py`. В них содержатся критичные ключи (токены Telegram, ID администраторов), дающие полный доступ к вашим серверам.
5. **Принцип наименьших привилегий:** Если бот не требует обязательного наличия прав `root` для тех модулей, что вы используете, запускайте его из-под выделенного ограниченного системного пользователя.

## Политика раскрытия информации
После получения информации об уязвимости мы:
1. Подтвердим её наличие.
2. Подготовим исправление в закрытой ветке.
3. Выпустим обновление (релиз).
4. Опубликуем публичный отчет об исправлении в CHANGELOG с благодарностью вам (если вы этого захотите).
