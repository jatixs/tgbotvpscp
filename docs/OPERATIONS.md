# Центр операций

Открывается по иконке истории рядом с фильтрами на странице мониторинга нод, адрес `/operations`.
Доступен владельцу и администраторам. Обычным пользователям история недоступна.
Выберите сервер и состояние, нажмите «Обновить». Ответ раскрывается в карточке команды.
Фильтры сохраняются в адресе страницы; для старых записей есть переход «Более ранние».
Время показано в UTC. Инициатор — Telegram ID пользователя, отправившего команду.

Один запуск мониторинга трафика в Telegram теперь занимает одну карточку. Замеры обновляют
её ответ и состояние, сохраняя номер и время начала; повторный запуск создаёт новую запись.
Пока предыдущий замер ожидает ноду или выполняется, новый не добавляется в очередь.
Уже существовавшие записи не объединяются задним числом. После перезапуска основного бота
мониторинг запускается заново, как и раньше.

Открытые карточки обновляются через одно SSE-соединение `/api/operations/stream`, без
перезагрузки страницы. Раскрытые ответы остаются раскрытыми. При уходе со страницы или
скрытии вкладки поток закрывается; при возврате подключается снова. Фильтры и пагинация
выбирают набор карточек при открытии страницы, кнопка «Обновить» повторяет выборку.
Переходы между мониторингом и историей, включая Back/Forward, выполняются внутри панели.

Имена серверов, команды, инициатор и ответы в HTML зашифрованы существующим AES-механизмом
панели. JSON API и содержимое SSE передаются в обёртке `{"d": "..."}` и расшифровываются
общими функциями клиента. HTTPS и серверная проверка сессии остаются обязательными.
Файлы истории `operations.js` и `operations.css` доступны только администратору; общие
файлы навигации требуют авторизации. Ответы помечены `no-store`. CSS и JS подключаются
из отдельных файлов; навигация не исполняет скрипты из загруженного HTML.

История охватывает команды удалённым нодам из Telegram и веб-панели, проходящие через
`nodes_db.update_node_task`. Действия на основном сервере, SSH-сеансы и обновления клиента
через отдельный механизм `NodeClientUpdate` в эту историю пока не входят.
Команды, завершённые до установки обновления, не восстанавливаются задним числом.

| Состояние | Что произошло |
| --- | --- |
| В очереди | Сервер сохранил команду; она ещё не выдавалась ноде. |
| Ожидаем подтверждения | Команда выдана в ответ на heartbeat. Подтверждение ноды ещё не пришло. |
| Выполняется | Нода записала начало выполнения в локальный журнал. |
| Ответ получен | Нода вернула результат. Для перезагрузки это подтверждение приёма команды, а не проверка успешного запуска. |
| Ошибка | Исполнитель вернул ошибку. |
| Результат неизвестен | Процесс ноды перезапустился до сохранения результата. Автоматического повторного запуска нет. |
| Отправлено без подтверждения | Задача выдана старой ноде, не поддерживающей журнал операций. |

## Обновление и совместимость

Сначала обновите основной сервер, затем ноды обычным способом. Новая таблица `node_operations`
создаётся при штатной инициализации ORM. Существующие задачи из `Node.tasks` переносятся
транзакционно при следующем heartbeat. Старые ноды продолжают получать прежний формат задач.
Обновлённая нода также может работать со старым основным сервером по прежнему протоколу.
При откате основного сервера новая очередь не будет видна старому коду: сначала дождитесь
завершения операций. Не удаляйте новую таблицу для отката.

Новый протокол использует случайный UUID операции. Сервер сохраняет отправку и результат
в SQLite, выдаёт максимум 20 команд и принимает максимум 100 отчётов за heartbeat.
Нода сохраняет начало выполнения **до** вызова команды. Повторная доставка одного UUID
не запускает команду повторно. До подтверждения сервера нода повторяет передачу результата.
Если журнал недоступен, нода продолжает передавать метрики, но получение новых команд
по надёжному протоколу приостанавливается до восстановления доступа к журналу.
Подтверждённый результат удаляется из локального журнала; идентификатор остаётся для защиты
от повторного выполнения. Журнал привязан к токену ноды и хранится в
`config/operations-<token-hash>.db`; оба установщика сохраняют его и служебные файлы SQLite.
Не удаляйте этот журнал на работающей ноде.

Если ответ heartbeat потерян, новая нода получит тот же UUID. При откате самой ноды на старую
версию команды, уже отправленные по новому протоколу, повторно старому клиенту не выдаются.
Надёжная доставка требует обновлённых обеих сторон и исправных дисков. Выполнение команды
и запись её результата не являются единой транзакцией: после аварийного завершения исход
может остаться неизвестным. В этом случае проверьте сервер перед ручным повтором действия.
Telegram-уведомления отправляются после сохранения результата; история остаётся источником
результата, даже если уведомление не удалось доставить.

Параметры и ответы зашифрованы в базе основного сервера существующим ключом проекта.
Токены и полный набор параметров команды не выводятся в карточках. Локальный журнал ноды
содержит ещё не подтверждённые ответы; доступ к каталогу конфигурации должен оставаться закрытым.
Автоматического удаления истории пока нет. Сохраняйте действующую базу `config/node.db`
(либо прежнюю `config/nodes.db`, если переименование не выполнялось) и ключ шифрования вместе.

## Проверки

`python -m unittest discover -s tests -v` запускает также отдельный процесс с настоящими
Tortoise ORM, SQLite и aiohttp. Проверяются потеря ответа, повторные команды, параллельная
постановка, перезапуск, совместимость, шифрование, права доступа, фильтры и экранирование HTML.
`node --test tests/*.cjs` проверяет существующие сценарии JavaScript.
Проверки установщиков работают только с временными каталогами и требуют Bash.
